# AI Agent v0.1 Documentation and Comment Cleanup Design

**Date:** 2026-09-01  
**Status:** Approved

## Goal

Make the AI-agent branch product-neutral, keep its newly added source comments in English, and document the implemented v0.1 feature set for users.

## Scope

The change is limited to content introduced by `master...ai-agent`:

- `docs/superpowers/specs/2026-08-31-emacs-ai-design.md`
- `docs/superpowers/plans/2026-08-31-emacs-ai.md`
- `init-v2.org` AI sections that tangle to `lisp/init-ai.el` and `site-lisp/omy-ai.el`
- a new user-facing document at `docs/ai-agent-v0.1.md`

`lisp/init-WeaveX.el`, existing non-AI configuration, API names beginning with `omy-ai`, model prompts, paths, and environment variables are out of scope.

## Documentation Changes

### Technical design and plan

Retain the existing design and implementation-plan files as historical engineering records. Remove external-product references, comparison language, and conceptual mappings. Replace them with direct descriptions of the Emacs AI-agent implementation.

### v0.1 feature guide

Add `docs/ai-agent-v0.1.md`. It is the current functional guide, not an implementation plan. It must cover:

1. Required API-key environment variables and the optional local vLLM backend.
2. `SPC a` session creation and reopening, including project-scoped file storage.
3. Org chat behavior: the `*** ` prompt, window-width wrapping, streaming follow, and expansion of reasoning blocks in the just-completed response.
4. Agent commands, AGENTS.md context injection, and the fact that write-capable tools act directly in the repository.
5. Minuet inline completion, default backend/model selection, and disabled model reasoning for completion requests.
6. The Git rollback boundary for direct repository writes.

The guide must describe only behavior that the current configuration provides.

## Source Comment Changes

Translate only comments, section headers, docstrings, interactive prompts, and user-visible error messages introduced in the AI branch. Use concise technical English. Preserve executable behavior and stable symbols exactly.

`init-v2.org` is the canonical source. Regenerate `lisp/init-ai.el` and `site-lisp/omy-ai.el` with Org Babel after the source translation; do not hand-edit generated files.

## Validation

1. Tangle `init-v2.org` and ensure the generated AI files match its source blocks.
2. Search the AI branch-owned source files for Han characters in comments, docstrings, interactive prompts, and user-facing messages. Remaining Han characters are allowed only in regex character ranges and non-comment data that is explicitly out of scope.
3. Search the documentation tree for removed external-product wording.
4. Run `tests/test-omy-ai.el` through the project batch Emacs test command.

## Non-goals

- Do not rename `omy-ai` symbols or data directories.
- Do not translate unrelated configuration comments.
- Do not alter backend endpoints, request payloads, key names, model names, or prompts.
- Do not add new runtime behavior beyond the existing v0.1 implementation.
